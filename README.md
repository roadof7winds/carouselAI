# carouselAI

Генератор каруселей для Instagram. Архитектура намеренно разделена по ролям —
никто не решает за другого:

```
Telegram-бот (приёмник)  →  очередь (pending)  →  LLM через MCP (понимание)  →  веб-редактор (витрина результата)
```

- **Бот** ничего не понимает. Он складывает входящие сообщения (текст + скачанные
  фото) в очередь со статусом `pending`. Не режет текст на слайды, не выбирает
  шаблон, не решает, какая картинка к какому слайду.
- **MCP-сервер** — окно в общее хранилище (шаблоны/карусели/очередь). Тоже ничего
  не решает, только отдаёт данные и принимает записи по вызовам инструментов.
  Живёт внутри `api`-сервиса, доступен по HTTP.
- **LLM** — единственное место, где происходит понимание. Подключаетесь к MCP-серверу
  сами (см. ниже), читаете правила (`rules/PROCESSING_RULES.md`) и очередь, решаете,
  что делать с текстом и фото, и пишете результат обратно через те же инструменты.
- **Веб-редактор** — витрина и ручная докрутка готового результата (текст/шрифт/
  цвет/подложка на лету), не зависит от Telegram.

## Быстрый старт

```bash
cp .env.example .env          # вписать TELEGRAM_BOT_TOKEN
docker compose up --build     # поднимает api (веб + MCP) и bot
```

- Веб-редактор: http://localhost:8000
- MCP-эндпоинт для подключения LLM: **`http://localhost:8000/mcp/`** — со слешем на
  конце, без него отдаст 405 (особенность монтирования MCP поверх FastAPI).

Без Docker — то же самое, но руками, в двух терминалах:

```bash
pip install -e ".[dev]"
pytest                                    # тесты ядра, MCP-инструментов, веб-API, очереди

python -m carouselai.web.app              # веб + MCP на http://127.0.0.1:8000
python -m carouselai.bot.main             # бот (нужен TELEGRAM_BOT_TOKEN в .env)
```

## Как подключить себя как LLM к MCP

Вы обрабатываете очередь вручную через свою сессию Claude (не автономный воркер).
Добавьте MCP-сервер в конфиг клиента (Claude Desktop, Claude Code и т.п.) как
удалённый HTTP-сервер по адресу `http://localhost:8000/mcp/` (или публичному адресу,
если `api` задеплоен). После подключения у LLM появляются инструменты:

**Очередь** (только это видит "непрочитанным" LLM):
- `get_processing_rules()` — прочитать актуальные правила обработки, **всегда
  первым делом**, они меняются без деплоя кода.
- `list_pending_items()` / `get_queue_item(id)` — что ждёт обработки.
- `read_queue_item_image(id, index)` — посмотреть фото элемента очереди (у LLM нет
  доступа к файловой системе бота, только через этот инструмент).
- `mark_item_processing(id)` → `mark_item_done(id, carousel_id)` /
  `mark_item_failed(id, reason)` — застолбить и закрыть элемент.

**Результат** (уже существовавшие инструменты генерации):
- `list_templates()`, `get_template(id)`
- `create_carousel(text, template_id)`
- `edit_slide(carousel_id, slide_index, text?, font_size?, font_color?, align?)`
- `set_template_background(template_id, image_path)` /
  `set_slide_background(carousel_id, slide_index, image_path)`
- `save_as_template(carousel_id, name)`
- `export_carousel(carousel_id)`

Полный алгоритм, что и в каком порядке вызывать — в `rules/PROCESSING_RULES.md`.
Редактируется как обычный текстовый файл, без кода.

## Компоненты в репозитории

- **core/** — вся бизнес-логика, ни от чего не зависит:
  `models.py` (`Template`, `Slide`, `Carousel`, `QueueItem`), `text_splitter.py`,
  `renderer.py` (Pillow), `template_store.py` / `storage.py` / `queue_store.py`
  (JSON на диске), `carousel_service.py` (склеивает всё в операции).
- **mcp_server/** — MCP-сервер (`MCPServer`, HTTP-транспорт) поверх
  `CarouselService`: и инструменты очереди, и инструменты генерации/правки.
- **web/** — FastAPI: REST для веб-редактора (`/api/...`), сам MCP примонтирован
  на `/mcp/`, статика фронтенда — на `/`. Один процесс, один порт.
- **bot/** — aiogram 3, только приём: текст/фото (в т.ч. альбомом) → запись в
  очередь, `/status <id>` — проверить статус элемента.

Данные (очередь, карусели, шаблоны, подложки) — в `data/` (или `/app/data` в
контейнере, общий volume между `api` и `bot`) — создаётся автоматически, в git не
попадает.

## Подложки

- **Подложка шаблона** — фон по умолчанию для всех слайдов этого шаблона, пока у
  конкретного слайда нет своей: `set_template_background(template_id, image_path)`,
  либо `POST /api/templates/{id}/background` в вебе.
- **Подложка слайда** — своя картинка для одного слайда одной карусели, не трогает
  остальные: `set_slide_background(carousel_id, slide_index, image_path)`, либо
  загрузка файла в карточке слайда в веб-редакторе.

Повторная загрузка заменяет предыдущую подложку, даже если у неё было другое
расширение файла.

## Что дальше (не реализовано)

- Отправка готового результата обратно в Telegram (сейчас результат смотрят и
  скачивают только в веб-редакторе) — если понадобится, `mark_item_done` уже
  знает `chat_id` элемента очереди, есть что использовать.
- Библиотека шаблонов с превью-картинками в веб-редакторе (сейчас — список по
  id/имени), создание нового шаблона "с нуля" через форму (API есть, кнопки в UI нет).
- Docker-образ собран и `docker compose config` проверен, но реальный запуск
  контейнеров в этой среде не проверялся (нет доступа к Docker-демону) — стоит
  прогнать `docker compose up --build` самостоятельно перед тем как полагаться на него.
- Автоподбор контраста текста под подложку, водяной знак/брендкит, экспорт под
  другие форматы (Reels-обложка, Stories).
